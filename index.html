A Flask application that splits a file into fixed-size blocks, encrypts each block with AES-256-GCM, stores the encrypted package locally or in Amazon S3, and restores the original file only when the key and SHA-256 check pass.

01 Overview

The application works in two modes. Local mode needs no AWS account. AWS S3 mode uploads the encrypted blocks and metadata to a private bucket, and downloads them back for restoration.

  • SegmentationFiles split into 256 KB to 4 MB blocks. Empty files and files smaller than one block are handled.
  • EncryptionAES-256-GCM with a fresh random 96-bit nonce per block. Block position and total count are authenticated.
  • Cloud storageBoto3 uploads to a private S3 bucket under files/{file_id}/. Only ciphertext and metadata leave the machine.
  • RestoreBlocks are decrypted in order, reassembled, and checked against the stored size and SHA-256 hash.

02 Pipeline

  1. INGEST The uploaded file is read into memory. Its name is sanitized.
  2. SEGMENT The file is cut into ordered blocks of the chosen size.
  3. ENCRYPT A new 256-bit key is generated. Each block is sealed with its own nonce.
  4. STORE The ZIP package (metadata.json and blocks/*.enc) is saved locally or uploaded to S3.
  5. RESTORE The package is opened with the key, blocks are decrypted, and the SHA-256 hash is verified.

03 Security design

  • The encryption key is never stored on the server, in S3, or in the activity log.
  • The S3 bucket keeps Block Public Access turned on. The app uses an IAM user limited to PutObject, GetObject, and ListBucket on the project prefix.
  • Uploaded filenames are sanitized to prevent path traversal.
  • The server listens only on localhost, with debug mode off.
  • A wrong key or a modified block fails authentication instead of returning corrupted data.

04 Hosting and content delivery

This documentation site is static HTML and CSS. It is stored in a separate S3 bucket and served through Amazon CloudFront over HTTPS. The bucket stays private, and CloudFront reads it using Origin Access Control.

  • Amazon S3 stores the files.
  • Amazon CloudFront caches them at edge locations worldwide and terminates HTTPS, redirecting HTTP to HTTPS.
  • HTTPS is provided by the default CloudFront certificate, with no certificate purchase needed.

05 Limitations

This is an educational prototype, not a production multi-user storage service. There are no user accounts, key management is manual, files are held in memory during processing, and the app has no rate limiting or audit trail beyond the in-memory log.

Built with Flask, boto3, and cryptography. Hosted on Amazon S3 with Amazon CloudFront.
